# 实盘可用性补全 设计文档（富途双策略真连交易）

> 日期：2026-06-23
> 范围：在已有运行时引擎(`94cbca5 wire runtime engine`)基础上，补齐让两套策略在富途上真正全自动交易所缺的数据与逻辑
> 目标终态：**直奔真连富途**（先模拟盘 SIMULATE，稳定后切 REAL），策略一/策略二端到端自动下单
> 前置：复用纯计算层 `backend/quant/`、运行时引擎 `backend/quant/live/runtime*.py`

---

## 1. 背景与问题

运行时引擎已接通骨架：`main.py` lifespan 启动 `LiveRuntime` → 连网关 → 订阅 → asyncio 循环
`run_once`(合成 bar → 调度 `due_actions` → 策略判定 → 风控 → 执行器 → 落库)。104 个测试通过。

但「策略在富途上自动交易」**尚不成立**，缺口集中在**数据写死**与**逻辑回路未闭合**：

- 策略一(日内)实际开不出单：`BarAggregator` 只从启动后的实时 tick 累积，缺历史分钟补种 → 真连后也要攒数小时才够算 15min MACD；MACD 反向交叉平仓 `reverse_cross=False` 写死；做空未接线(只处理 `enter_long`)。
- 策略二(中长线)筛选「放水」：`_default_fundamentals` 返回写死假基本面、停牌/除权/公告字段恒为 `False`；`holding_days=0` 写死 → 满 6 月调仓失效。
- 横跨两者：`daily_loss_pct=0.0` 写死 → 3% 熔断永不触发；后台改参数不影响 runtime；真连富途链路未本地验证。

本设计补齐上述缺口，不重构既有架构。

## 2. 决策（已与用户确认 2026-06-23）

- **目标终态**：直奔真连富途（非「先做扎实模拟」）；先 SIMULATE 后 REAL。
- **数据源**：富途为主（历史K线/实时行情/停牌-除权）+ 免费源补基本面（akshare 港股 / yfinance 美股财报）。
- **做空**：本轮启用。runtime 接通 `enter_short` + 可做空名单；不在名单的空头信号只记录不下单。
- **结构**：一个 spec，拆 3 个 plan（数据真实化 → 策略闭环 → 富途真连）。

## 3. 架构与改动全景

**不改动运行时架构**，只把「空接头」接上真实来源、闭合逻辑回路。数据流目标：

```
富途历史分钟K ──┐
富途实时 tick ──┴→ BarAggregator(补种 + 实时) → 5m/15m bar → 策略一(多/空)
富途历史日线 ─────→ data_provider → 日/周/月重采样 + 真实基本面 → 策略二
富途账户回报 ─────→ 当日权益基线 → daily_loss_pct → 3% 熔断(闩锁)
```

## 4. Plan 1 — 数据真实化

### 4.1 历史分钟补种（策略一命门）
- `gateway.py` 新增 `query_history_minute(symbol, count) -> list[Bar]`：富途历史 1 分钟 K。
- `BarAggregator.seed_minute_bars(symbol, bars)`：灌入 `_minute_bars`；`interval_bars` 照常按需聚合 5m/15m。`max_bars` 提到 ~1500（底背离回看 28 根 15m ≈ 420 根 1min + MACD 预热）。
- 接线：盘前选股得 watchlist → `subscribe` 时**每标的每日补种一次** → 开盘即可算 MACD。
- 实时 tick 仍走 `ingest_tick`，与补种拼接。历史 K 线 volume 与实时累计 volume 语义差异在本地核对（`_merge_bars` 现以末值减首值估算 interval volume）。

### 4.2 基本面 adapter（策略二）
- 新增 `quant/data/fundamentals.py`：`load_fundamentals(symbol, market) -> FundamentalSnapshot`，可注入、季度级缓存。
- `market_cap`、`positive_profit_quarters`(近2季净利润为正) → yfinance(美股) / akshare(港股) 财报。
- `has_major_risk`(退市/立案/违约) → **维护式黑名单**（配置文件，无干净免费 API）。
- `data_provider.py` 删 `_default_fundamentals`，`portfolio_rows()` 改调 `load_fundamentals`。

### 4.3 停牌/除权/公告（策略一禁选）
- 新增轻量 `MarketInfoProvider` 填 `IntradayCandidate` 的 `halted/ex_dividend_soon/major_news`：
  - `halted`、`ex_dividend_soon` → 富途快照/静态信息（可得性 Plan 3 本地确认）。
  - `major_news` → 维护式黑名单。
- 拿不到的字段**默认走安全侧**（宁可不选，不错选）。

### 4.4 可做空名单
- `SymbolInfo` 加 `shortable: bool=False`（手工配）。策略一空头入场前查。

### 4.5 测试
- 外部源全部走注入式 loader/provider，远程用 fake 数据单测（沿用 `loaders` 可注入模式）。真实源连通留 Plan 3。

## 5. Plan 2 — 策略闭环补全（纯逻辑）

### 5.1 当日权益基线 → 3% 熔断
- `runtime_state.py`：`reset_for_day` 清基线；当日**首笔非空账户回报**记 `day_start_equity = account.balance`；`daily_loss_pct = (balance − 基线)/基线 × 100`。
- `runtime.py`：替换写死的 `daily_loss_pct=0.0`(185、337 行)为真值。
- **熔断闩锁**：当日触发 −3% 即置 `halted_today=True`，当日剩余时间一律拦截开仓（即使权益回升），对齐「触发后当日停止所有交易」。

### 5.2 holding_days → 满 6 月调仓
- 建仓日期来源：**已落库的开仓成交时间**(store)；启动时回放重建，运行中缓存到 runtime_state。
- `runtime.py` `_run_portfolio_exits`：`holding_days=0`(305 行)换成 `(今天 − 建仓日).days`。重启不丢。

### 5.3 MACD 反向交叉平仓
- `_run_intraday_exits`：从标的 15m bar 算 MACD；多头持仓看死叉(`has_bearish_cross`)、空头看金叉(`has_bullish_cross`)，真值 `reverse_cross` 传入 `evaluate_intraday_exit_signal`（替换 212 行写死 `False`）。

### 5.4 做空接线
- `_run_intraday_entries`：多头不成立且标的 `shortable=True` 时再评估空头(`build_intraday_decision(side="short")`)→ `execute_intraday_entry(is_short=True, shortable=...)`。
- 空头出场(`_pnl_pct` 已按 side 算) + 风控 `is_short/shortable` 传通。
- 不在名单的空头信号：只记录不下单（落 signal 日志）。

### 5.5 参数注入
- 新增 `LiveParams` 单一参数源（intraday + portfolio 两组，默认值 = 现有函数默认），参数接口校验后更新。
- runtime 调用策略/执行器时读当前 `LiveParams`（stop_loss_pct、position_fraction_pct、single_position_cap_pct、max_positions…），不再用函数默认。
- `AppState` 与 runtime 共享同一 `LiveParams` 引用；`update_strategy_params` 改它即时生效。

### 5.6 测试
- 全纯逻辑，远程构造 fake 账户/bar/持仓覆盖：熔断触发+闩锁、满6月边界、反向交叉多空、做空入场+名单拦截、参数改后行为变化。

## 6. Plan 3 — 富途真连联调（本地）

### 6.1 真连开关串联
- `LIVE_RUNTIME_ENABLED=1` + `LIVE_RUNTIME_DRY_RUN=0` + `FUTU_TRD_ENV=SIMULATE`（先模拟盘）。`build_live_runtime_from_env` 已在非 dry-run 走 `FutuLiveGateway`，补通端到端。
- 切实盘需 `FUTU_TRD_ENV=REAL` + `FUTU_REAL_TRADING_CONFIRM`（已有真钱保护闸）。

### 6.2 本地必须核对（只有用户本机连 FutuOpenD 能验）
1. `send_order` 中文枚举：`Direction("多"/"空")`、`Offset("开"/"平")`、`OrderType.LIMIT` 对当前 vnpy_futu 版本是否成立（美股可能走 NET 方向）。
2. 历史K线接口：`query_history_minute` 走 vnpy `query_history` 还是 futu-api 直连。
3. 停牌/除权字段实际可得性，拿不到退回黑名单。
4. 行情订阅额度 vs 自选池规模（富途有上限）。
5. symbol 格式 / 交易所映射(`.HK`/`.US` ↔ SEHK/SMART) 往返正确。

### 6.3 整体验证策略
- **远程(CI)**：Plan 1 adapter 用 fake loader 单测、Plan 2 闭环全单测；现有 104 测试保持全绿。
- **本地**：`futu-gateway-local-verify.md` 扩成完整清单——连接→账户回报→订阅行情→历史补种→盘前选股(真实数据)→模拟下单(多/空/开/平)→回报回流→持仓/熔断/尾盘清仓。
- **观察期**：SIMULATE 跑若干交易日核对日志/选股/信号/成交符合规则，再切 REAL。

## 7. 明确的简化与边界（YAGNI / 收口）

- 策略二止盈「20%-35%分批」→ 单档（盈≥20%减半 + 顶背离/破位全清），不做 35% 中间档。
- 「重大公告/退市/立案/违约」→ 维护黑名单，非自动抓取。
- 自选池 `universe.py` 现仅 3+3 示例，需用户按实际自选股扩充（手工配置）。
- 全市场实时订阅：仍仅自选池（富途行情额度限制），不做全市场。
- 老虎通道、MT5：不做（沿用既有架构决策）。

## 8. 成功标准

- Plan 1+2 远程测试全绿（含新增 adapter/闭环单测），现有 104 测试不回归。
- 本地 SIMULATE：两套策略按本文档规则自动选股/开平仓/止盈止损/熔断/调仓，下单回报正确回流并落库、看板显示真实状态。
- 「功能完成」= 系统按需求文档规则全自动运行；不等同盈利或零缺陷，REAL 前需观察期。
