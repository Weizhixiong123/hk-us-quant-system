## 1. 目标与边界

### 1.1 本期目标
在**不需要任何券商账号**的前提下，验证两套策略的逻辑与盈利能力：

1. 历史数据层：免费源(美股 yfinance / 港股 akshare) → vnpy SQLite 数据库，含日线→周线/月线重采样
2. 指标与规则库：复用现有 MACD/背离/金叉纯函数，补齐策略二多周期均线、零轴、基本面筛选
3. 选股扫描：策略一每日开盘前筛选、策略二大级别+基本面+回撤筛选(独立可单跑)
4. 回测引擎：**严格采用 vnpy** (`vnpy_ctabacktester` + 组合回测引擎)，跑两套策略完整入场/出场/止盈止损/尾盘清仓/调仓
5. 参数优化 + 回测报告(收益/回撤/夏普/胜率 + 资金曲线)
6. 回测结果接回现有 FastAPI `/backtests` 与 Vue 看板，替换当前写死的假回测

### 1.2 本期明确不做(留待第二期)
- Futu / Tiger 真实网关联调、实时行情订阅、模拟盘/实盘下单
- vnpy 在本期仅作为回测与数据底座，其核心价值(实盘网关)留到第二期
- 不写无法验证的网关代码以免积压

### 1.3 关键现实约束
- **vnpy 依赖较重，开发用的远程机大概率无法安装/运行**；vnpy 策略与回测代码的运行验证需在用户本地完成
- 纯函数(指标/选股/风控)可在远程编写并单元测试验证
- 选股范围：**限定自选股池**(用户维护的候选标的，几十到上百只)，不做全市场实时订阅
- 数据额度：分钟级历史数据受免费源/券商额度限制，回测可用深度需实测(yfinance 美股分钟数据约近 60 天；港股分钟数据较弱，必要时降级)

## 2. 架构方案

**方案 C(vnpy 框架)** — 与开发方案文档一致。

回测引擎选型：**方案 ②，严格使用 `vnpy_ctabacktester` + 组合回测引擎**(用户拍板)。

由此带来的核心妥协：vnpy 回测吃**固定标的池**，而两策略本质是**动态选股**。解决办法见 §4 数据流的"动态选股绕路方案"。

## 3. 目录结构

在 `backend/` 下新增 `quant/` 包，**不改动现有 `app/`** 的对外行为：

```
backend/quant/
  data/
    feeders.py        # 免费源(yfinance/akshare) → vnpy BarData → vnpy_sqlite
    resample.py       # 日线 → 周线/月线 重采样
    universe.py       # 自选股池配置(HK/US 分组)
  indicators/
    macd.py           # 复用 app/strategies/macd_intraday.py 的纯函数
    divergence.py     # 顶/底背离(从现有代码抽出)
    trend.py          # 均线 / 零轴 / 多头排列 / 回撤
  screening/
    intraday_screener.py   # 策略一每日开盘前选股
    portfolio_screener.py  # 策略二大级别 + 基本面 + 回撤选股(复用 trend_portfolio.py)
  strategies/
    intraday_macd_cta.py        # 策略一 CtaTemplate 实现
    trend_portfolio_strategy.py # 策略二 PortfolioStrategy 实现
  backtest/
    run_intraday.py   # vnpy CTA 回测封装
    run_portfolio.py  # vnpy 组合回测封装
    report.py         # 绩效报告(收益/回撤/夏普/胜率/资金曲线)
  risk/
    rules.py          # 复用 app/services/risk.py
```

**复用原则**：现有 [macd_intraday.py](../../../backend/app/strategies/macd_intraday.py)、[trend_portfolio.py](../../../backend/app/strategies/trend_portfolio.py)、[risk.py](../../../backend/app/services/risk.py) 的纯函数抽到 `quant/indicators`、`quant/screening`、`quant/risk` 复用，不重写。原文件可保留为薄转发或迁移后删除(实现期决定)。

## 4. 数据流

```
免费源(yfinance / akshare)
   └─ data/feeders.py ──→ vnpy BarData ──→ vnpy_sqlite(日线 / 分钟)
                                              │
   resample.py: 日线 → 周线 / 月线            │
                                              ▼
选股模块(回放历史) ──每期 universe──→ vnpy 回测引擎(CTA / 组合)
   ├─ intraday_screener (策略一每日)              │ 撮合 + 滑点 + 绩效
   └─ portfolio_screener (策略二大级别+基本面)     ▼
                                          report.py(收益/回撤/夏普/胜率/资金曲线)
                                              │
                                   写回 SQLite/JSON ──→ FastAPI /backtests ──→ Vue 看板
```

### 动态选股 × vnpy 固定标的池的绕路方案
1. 选股模块先**回放历史**，逐期(策略一逐日、策略二逐月)算出入选标的列表，持久化为"选股历史"。
2. 策略一：对历史上曾入选的日内标的**逐个跑单标的 CTA 回测**，再按当日选股结果与仓位规则(同时 ≤3 只)汇总成组合绩效。
3. 策略二：把每月选出的标的喂给**组合回测引擎**，按月度调仓重置 universe。

## 5. 策略规则代码化(默认参数)

参数全部可配置，下列为回测默认值；§5.6 模糊规则的默认数学定义沿用现有代码实现。

### 5.1 策略一 · 日内 MACD(CtaTemplate)
- 周期：15min 主信号 + 5min 二次确认(vnpy `BarGenerator` 从基础周期合成)
- MACD：EMA 12 / 26 / DEA 9(固定)
- **每日选股**(intraday_screener)：日均成交额 ≥ 500 万(按市场币种)、前一日振幅 ∈ [2%, 8%]、股价 ≥ 2、排除停牌/即将除权除息/重大公告
- 多头入场：15min 绿柱缩短 + 底背离 + 金叉；5min 金叉确认；价站上 15min 5MA；时间窗 = 开盘 30min 后 ~ 收盘前 90min
- 空头入场：对称条件 + 可空校验(回测期可开关，默认仅多头以贴合多数账户)
- 出场(优先级 止损 > 止盈 > 尾盘)：亏 1.5% 止损；盈 2% 平半、盈 3.5% 全平、MACD 反向交叉全平；收盘前 10min 强制清仓
- 仓位/风控：单标的单次 10%；同时持仓 ≤ 3；同标的当日止损后禁开、不加仓；单日账户亏损 3% 当日停止

### 5.2 策略二 · 中长线选股持仓(PortfolioStrategy)
- 周期：月线/周线选股 + 日线择时
- 选股(portfolio_screener)：月线站上 20/60 月线且 MACD 双线零轴上方；周线 5/10/20 多头排列、无顶背离、红柱延续、高低点抬高；基本面近 2 季净利为正、无退市/立案/违约、流通市值 港股≥50亿/美股≥20亿美金；近 3 月最大回撤 ≤15%
- 日线择时建仓：回踩 20/30 日均线企稳；MACD 无破位死叉或小回调再金叉；无放量大跌
- 出场调仓：月线跌破 60 月线连 2 月清仓 / 周线 5 周下穿 10 周止损 / 月线 MACD 跌破零轴清仓；盈 20%~35% 减半、周/月线顶背离清仓、持仓满 6 月调仓；每月最后交易日重跑选股
- 仓位/风控：单只 ≤15%；总持仓 5~8 只；分 2 次建仓(首次 6 成、回踩补满);单标的回撤 18% 止损；短期涨幅 >40% 禁新建仓

### 5.3 基本面数据(策略二风险点)
优先用券商/免费源财务字段；缺口字段降级为 `universe.py` 中手动配置。回测期若基本面数据不可得，允许以"仅技术面"模式跑通并在报告中标注。

## 6. 接口与数据契约

- 复用现有 [schemas.py](../../../backend/app/models/schemas.py) 的 `BacktestRequest` / `BacktestResult`，**不改前端契约**
- `BacktestResult.notes` 用于承载"选股口径、数据深度、模糊规则取值、是否仅技术面"等说明
- FastAPI `/backtests` 由现有假实现([state.py](../../../backend/app/services/state.py) `run_backtest`)改为调用 `quant/backtest` 真实回测；回测耗时较长，采用同步返回 + 结果落库(后续可改异步任务)
- 回测结果落库 SQLite(独立于 vnpy 数据库的应用表)，供 `/backtests` 历史查询
