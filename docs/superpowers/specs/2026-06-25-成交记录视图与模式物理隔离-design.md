# 成交记录视图 + 模式物理隔离 设计文档

> 日期：2026-06-25
> 范围:① 成交记录全屏视图(点「最近成交」/导航「成交记录」进入,看完整成交历史);② 干跑/模拟盘/实盘按**独立数据库文件物理隔离**,实盘数据绝不混入测试。

---

## 1. 背景与问题

当前三种模式(干跑 / 模拟盘 / 实盘)的成交、订单、信号等事件**全落到同一个 `data/live.sqlite3`,无模式标记**。切模式(热重载)后内存成交清空,但数据库历史混在一起。给客户用时,**实盘真实成交会混入干跑/模拟的假数据**,既乱又危险。同时「最近成交」只显示 4 条、箭头不可点,看不到完整开仓历史。

## 2. 决策(已与用户确认 2026-06-25)

- **物理隔离**:每种模式用独立 db 文件(干跑 / 富途SIMULATE / 富途REAL / 老虎sandbox / 老虎live)。
- **AppState 查询时动态**按当前模式算 db 路径 → 热重载切模式后立即读对库。
- 成交记录视图 + 「最近成交」卡片**明确标注当前模式**。
- 成交范围:所有成交(开+平);底部三栏箭头都接通。

## 3. 架构与改动

### 3.1 模式 → 数据库文件(后端核心,纯逻辑可测)

新增 `live_db_path_for_mode(settings: Mapping) -> Path`(放 `quant/live/store.py`):

| runtime 配置 | 文件 |
|---|---|
| `dry_run=true` | `data/live-dry_run.sqlite3` |
| futu + SIMULATE | `data/live-futu-simulate.sqlite3` |
| futu + REAL | `data/live-futu-real.sqlite3` |
| tiger + sandbox | `data/live-tiger-sandbox.sqlite3` |
| tiger + live | `data/live-tiger-live.sqlite3` |

实现:`dry_run` 优先 → `dry_run`;否则 `{broker}-{futu.trd_env | tiger.environment}`,小写。文件名 `data/live-{tag}.sqlite3`,与 `DEFAULT_DB_PATH` 同目录。

### 3.2 runtime 与 AppState 使用当前模式库

- `build_live_runtime_from_env`:`db_path = live_db_path_for_mode(load_live_settings())`,传给 `LiveRuntime`,落库到对应文件。
- `AppState` 查询(`_live_watchlist` / `_live_signals` / 新增 `trade_history`):db 路径**动态**取 `live_db_path_for_mode(load_live_settings())`(不再固定构造时的 `db_path`)。这样热重载切模式后自动跟随。
  - `AppState.db_path` 参数保留(测试可注入覆盖动态计算);为 None 时走动态。

### 3.3 成交历史查询

- `AppState.trade_history(limit=200) -> list[Trade]`:`list_live_events(kind="trade", db_path=<当前模式库>)` → 转 `Trade`(复用 `_live_trades` 的转换或 payload 映射)。
- 新增 `GET /api/trades/history` → `trade_history()`。

### 3.4 前端成交记录视图

- `ViewName` 加 `"trades"`;`ops-content` 在 `activeView==='trades'` 时渲染成交记录视图(全屏成交列表组件,复用现有表格样式)。
- 「最近成交」卡片 header(箭头/标题)`@click="activeView='trades'"`;底部三栏箭头分别接通 持仓→后续 / 成交→`trades` / 事件→后续(本期至少接通成交;持仓/事件视图占位或一并简单接通)。
- 左导航「成交记录」项加 `view: "trades"`。
- 视图顶部 + 「最近成交」卡片标注当前模式(读 `account.source` / health 的 `runtime_dry_run`+`runtime_broker`,显示「干跑 / 富途模拟盘 / 富途实盘…」)。

## 4. 测试

- **远程 TDD**(纯逻辑):`live_db_path_for_mode` 各模式映射;`trade_history` 从注入库读 trade 事件转 Trade;切模式后 AppState 读对库(注入两套 settings/db)。
- **本地**:`GET /api/trades/history`(fastapi);前端 `vue-tsc`;真连切模式落库隔离观察。

## 5. 边界 / YAGNI

- 不做跨模式合并/对比查询(各看各的)。
- 不迁移现有 `live.sqlite3` 旧数据(新文件从空开始;旧文件保留不动)。
- 持仓/订单/事件的完整历史视图:本期成交优先;持仓/事件箭头可先接到占位或最小视图。
- 不做成交记录的分页/筛选(取最近 N 条)。

## 6. 成功标准

- 干跑/模拟盘/实盘各自落到独立 db 文件,互不可见对方成交。
- 切模式(热重载)后,看板与成交记录立即读当前模式的库。
- 点「最近成交」或导航「成交记录」→ 全屏成交历史,顶部标注当前模式。
- 远程逻辑测试全绿;本地 API/前端验证通过。
