# 港美股双策略实盘自动交易系统 设计文档

> 日期：2026-06-22
> 范围：两套策略的全自动实盘交易系统(先模拟盘 SIMULATE,稳定后切实盘)
> 路线：vnpy 做富途网关、自建做策略与调度、FastAPI+Vue 不变,单体进程
> 前置：复用已合并的纯计算层 `backend/quant/`(标的池/数据加载/重采样/指标/选股)

---

## 1. 目标与边界

### 1.1 目标
实现需求文档的核心——一套**全自动程序化交易系统**,两套策略独立可开关:
- 策略一(日内 MACD):盘前选股 → 自动入场 → 止盈止损 → 收盘前 10 分钟强制清仓,T+0 不隔夜
- 策略二(中长线):月末选股 → 日线择时分批建仓 → 出场调仓,持仓 1~6 月
- 风控强制锁定、交易日志、参数后台可改、富途网关对接

### 1.2 本设计明确不做(YAGNI)
- **回测**:需求文档未要求,已与用户确认跳过(纯计算层的选股/指标仍复用)
- 老虎(Tiger)通道:本期仅富途;网关层抽象保留扩展点
- MT5:与富途路线互斥,不做(开发方案 §8.6)
- 策略一**空头**:默认仅多头(港股可空名单/美股借券复杂),代码留可空校验扩展点

### 1.3 关键现实约束
- **vnpy + FutuOpenD + 富途凭证只能在用户本地运行**;开发机(远程)无法安装 vnpy、无法连富途。涉及真实连接/行情/下单的代码,联调验证必须本地完成。
- 纯逻辑模块(时钟/调度/策略判定/风控/选股/持久化)可在远程单元测试验证。
- **先模拟盘**(`trd_env=SIMULATE`):免解锁、仅限价/市价、仅当日有效单、查不到成交费用(开发方案 §4.1)。模拟盘只验证逻辑与链路,不代表实盘盈利。
- 富途实时行情订阅有额度上限,**只对自选股池订阅**,不做全市场实时。

## 2. 架构与进程模型

单 FastAPI 进程,vnpy 引擎跑在后台线程:

```
FastAPI 单进程
├─ vnpy MainEngine(后台线程,EventEngine 基于线程+队列)
│   └─ FutuGateway → 本地 FutuOpenD → 富途(先 SIMULATE)
│        ├─ 实时行情订阅(tick / 分钟K)
│        ├─ 下单 / 撤单
│        └─ 回报回调:onTick / onOrder / onTrade / onPosition / onAccount
├─ 调度引擎(asyncio,交易日历 + 交易时段感知)
│   ├─ 策略一节奏:盘前选股 · 5min/15min 收线信号 · 收盘前10min清仓
│   └─ 策略二节奏:月末选股 · 每日收盘后择时/出场评估
├─ 策略逻辑(复用 quant/screening + quant/indicators)
├─ 风控(下单前强制校验,复用并扩展 quant/risk)
├─ 执行器(信号 → 风控 → 网关下单 → 回报 → 更新状态/日志)
├─ 持久化(SQLite:交易日志/信号/选股/成交/持仓快照)
└─ Web 状态层(真实引擎状态替换 state.py 随机模拟)→ REST/WS → Vue
```

**关键设计点**:
- vnpy EventEngine(线程模型)与 FastAPI(asyncio)桥接:网关回调在 vnpy 线程触发,写入**线程安全的共享状态**(加锁)与 SQLite;FastAPI/WebSocket 从共享状态读。
- 策略代码只依赖统一的内部接口(行情快照 / 下单意图),**不感知富途与模拟/实盘**;切换只在网关配置(`trd_env`)。

## 3. 模块分解

新增 `backend/quant/live/`(或按下表路径),现有 `quant/` 纯计算层复用,`app/` Web 层改造:

| 模块 | 路径 | 职责 | 远程可验证 |
|---|---|---|---|
| 网关封装 | `quant/live/gateway.py` | vnpy FutuGateway 接入:连接、订阅、下单、撤单、回报转内部事件 | ❌ 本地 |
| 交易时钟 | `quant/live/clock.py` | 港美股交易日历、交易时段、开盘后30min、收盘前90min/10min 判定 | ✅ |
| 调度引擎 | `quant/live/scheduler.py` | 按策略节奏触发 hook(盘前/收线/尾盘/月末) | ✅ 逻辑 |
| 策略一 | `quant/live/intraday.py` | 选股→入场判定→持仓监控(止损/阶梯止盈/反向交叉)→尾盘清仓 | ✅ 逻辑 |
| 策略二 | `quant/live/trend.py` | 月末选股→日线择时分批建仓→出场调仓 | ✅ 逻辑 |
| 风控 | `quant/risk/rules.py`(扩展) | 下单前强制校验:单日熔断、仓位、同时持仓数、止损后禁开、PDT、可空 | ✅ |
| 执行器 | `quant/live/executor.py` | 信号→风控→生成下单意图→网关下单→回报更新持仓/日志 | ⚠️ 逻辑可测,下单本地 |
| 持久化 | `quant/live/store.py` | 日志/信号/选股/成交/持仓快照入 SQLite | ✅ |

| Web 接入 | `app/services/state.py`(改造) | 读实盘共享状态,替换随机模拟;策略开关/参数 | ✅ |

每个模块单一职责、接口清晰,可独立测试。

## 4. 数据流

```
实时行情(富途) ──→ 网关 onTick/onBar ──→ 合成多周期(5m/15m;日/周/月由历史) 
                                              │
历史K线(富途历史 或 loaders:yfinance/akshare) ┘
                                              ▼
                          策略逻辑(选股 + 入场/出场判定)产生信号
                                              ▼
                          风控前置校验(不通过则拦截并记录)
                                              ▼
                          执行器 → 网关下单 → 富途回报(成交/订单)
                                              ▼
                  更新持仓/账户/日志/信号状态(共享状态 + SQLite)
                                              ▼
                          FastAPI REST/WS → Vue 看板
```

策略一需要 **5min/15min** 多周期:由实时行情合成当日 bar,叠加历史分钟数据算 MACD/背离/5日线。
策略二需要 **日/周/月** 大级别:日线为主,周/月由日线重采样(复用 `quant/data/resample`)。

## 5. 策略规则代码化(默认参数,全部后台可改)

### 5.1 策略一 · 日内 MACD(`quant/live/intraday.py`)
- 周期:15min 主 + 5min 确认;MACD 12/26/9(固定)
- 盘前选股(复用 `intraday_screener`):日均成交额≥500万(按市场币种)、前一日振幅∈[2%,8%]、股价≥2、排除停牌/即将除权除息/重大公告
- 多头入场(全满足):15min 绿柱缩短 + 底背离 + 金叉;5min 金叉确认;价站上 15min 5日线;时间窗=开盘30min后~收盘前90min
- 空头:默认关闭(可空校验扩展点)
- 出场(优先级 止损>止盈>尾盘):亏1.5%止损;盈2%平50%、盈3.5%全平、MACD反向交叉全平;**收盘前10min强制清仓**
- 仓位/风控:单标的单次10%;同时持仓≤3;同标的当日止损后禁开、不加仓;单日账户亏损3%→当日停止所有交易

### 5.2 策略二 · 中长线(`quant/live/trend.py`)
- 周期:月/周线选股 + 日线择时
- 选股(复用 `portfolio_screener`):月线站上20/60月线且MACD双线零轴上;周线5/10/20多头排列、无顶背离、高低点抬高;基本面近2季盈利、无退市/立案/违约、流通市值 HK≥50亿/US≥20亿美金;近3月最大回撤≤15%
- 日线择时建仓:回踩20/30日均线企稳;MACD无破位死叉或小回调再金叉;无放量大跌
- 出场调仓:月线跌破60月线连2月清仓 / 周线5周下穿10周止损 / 月线MACD跌破零轴清仓;盈20%~35%减半、周/月线顶背离清仓、满6月调仓;每月最后交易日重跑选股
- 仓位/风控:单只≤15%;总持仓5~8只;分2次建仓(首次6成、回踩补满);单标的回撤18%止损;短期涨幅>40%禁新建仓

### 5.3 §5.6 模糊规则(开发方案标注)
背离波峰波谷/回看根数、红绿柱"持续缩短"根数、5日线"站稳"容差——沿用 `quant/indicators` 现有数学定义为默认值,作为后台可调参数。

## 6. 风控与安全(下单前强制锁定)

执行器在**每次下单前**调用风控,任一不通过则拦截并记录日志:
- 单日账户亏损达3% → 当日停止所有交易(熔断状态机)
- 日内同时持仓≤3;策略二总持仓5~8、单只≤15%、策略一单次10%
- 同标的当日止损后禁开;不加仓/不补仓
- 美股 PDT:净值<$25k 保证金账户,5日内≤3笔日内交易,内置计数与拦截
- 可空校验:空头标的需在可空名单(本期空头默认关闭)
- 异常处理:网关断线→暂停开新仓并告警;下单被拒→记录并不重试危险操作

## 8. 实现分批(按风险从低到高,各自独立成 plan)

1. **Plan A — 网关层**:vnpy 富途网关封装 + 连接/行情订阅/账户查询(本地验证链路)
2. **Plan B — 引擎底座**:交易时钟/日历 + 调度 + 执行器骨架 + 风控前置(纯逻辑远程验证)
3. **Plan C — 策略一实盘**:盘前选股→入场→出场→尾盘清仓全闭环
4. **Plan D — 策略二实盘**:月末选股→日线择时建仓→出场调仓
5. **Plan E — Web 接真实数据**:共享状态接入 REST/WS、策略开关/参数后台、持久化展示

每个 plan 产出可独立测试的成果。Plan A 需本地联调,B~E 的纯逻辑部分远程可验证、下单环节本地验证。
